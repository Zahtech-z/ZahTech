# Documentation Standards

**Status:** Draft

- Maintain a clear distinction between company-wide standards and product-specific facts.
- Use ADRs for significant architectural decisions, including context, alternatives, decision, and consequences.
- Write runbooks from implemented and tested procedures, not from proposed infrastructure.
- Record assumptions, unresolved questions, owners, and verification status.
- Update documentation in the same change as behavior or process changes where practical.
- Keep handoff notes concise, actionable, and linked to evidence.
